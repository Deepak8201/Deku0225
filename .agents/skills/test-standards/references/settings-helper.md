# SettingsHelper Patterns (Gap 4)

Centralized access to environment configuration for URLs, credentials, OAuth, and API clients. **Never hardcode** application URLs, passwords, or client secrets in test or page code.

Imports use `{config.importBasePath}`:

```typescript
import { SettingsHelper } from '{config.importBasePath}/SettingsHelper';
```

---

## Environment configuration

- **Source**: the generated `environment-configuration.json` — resolved by `SettingsHelper` in priority order:
  1. pipeline file `/tmp/clone/environment-configuration.json`;
  2. local file `{paths.envConfig}` — `environment-configuration/local-environment-configuration/environment-configuration.json` (relative to `{rootFolder}`, generated by `environment-configuration/setEnvironmentScript.ps1`);
  3. the `ATP_ENVGENE_CONFIGURATION` environment variable — **deprecated backward-compat fallback only**, never the source of truth.
- The first source that exists wins. A file always beats the variable, so setting the variable cannot override a generated config file.
- **Parsed once** (cached) via `SettingsHelper.getEnvConfig()` until `reloadEnvConfig()` is called.
- **Shape** (logical):

```json
{
  "systems": [
    {
      "YourSystemName": {
        "connections": [
          { "HTTP": { "url": "https://...", "username": "...", "password": "..." } },
          { "DB": { "host": "...", "port": "5432", "database": "..." } }
        ]
      }
    }
  ]
}
```

### Configuration path rule

Resolution follows:

**`systems[]` → `{systemName}` → `connections[]` → `{connectionType}` → `{param}`**

- **`systemName`** — logical application or gateway name (e.g. `CSRD`, `public-gateway`). **Always required** on public SettingsHelper APIs.
- **`connectionType`** — e.g. `HTTP`, `DB`, `SSH`. Many helpers default to **`HTTP`** when omitted.
- **`param`** — e.g. `url`, `username`, `password`, `tokenEndpoint`, `grantType`, `clientId`, …

Low-level access:

```typescript
// Throws if missing
SettingsHelper.getEnvParam(systemName, connectionType, paramName);

// Returns null if missing
SettingsHelper.getEnvParamOrNull(systemName, connectionType, paramName);
```

## SettingsHelper.getBaseUrl(systemName)

Returns the base **HTTP** URL for the system (default connection type `HTTP`).

```typescript
const baseUrl = SettingsHelper.getBaseUrl('CSRD');
// Equivalent: SettingsHelper.getBaseUrl('CSRD', 'HTTP');
```

Use this for `page.goto`, workflow entry points, and any UI navigation base. Combine with app-specific paths or `getFullUrl` when a `startPage` fragment is configured.

---

## SettingsHelper.getDefaultCredentials(systemName)

Returns `{ username, password }` from the **HTTP** connection (by default).

```typescript
const { username, password } = SettingsHelper.getDefaultCredentials('CSRD');
```

For alternate connection types (e.g. dedicated SSH or DB user):

```typescript
const creds = SettingsHelper.getDefaultCredentials('CSRD', 'SSH');
```

**No literals**: read usernames/passwords only from configuration.

---

## SettingsHelper.getOAuthConfig(systemName)

Builds an `OAuthConfig` object from the **HTTP** connection (default):

- Required params typically include: `url`, `tokenEndpoint`, `grantType`
- Optional: `clientId`, `clientSecret`, `scope`, `username`, `password` (when present in env JSON)

```typescript
const oauth = SettingsHelper.getOAuthConfig('public-gateway');
// oauth.tokenEndpoint, oauth.grantType, optional clientId, etc.
```

---

## SettingsHelper.getAPIConfiguration(systemName)

Returns API client settings (default **HTTP** connection):

- Always includes resolved `url`
- Sets sensible default headers (`Content-Type`, `Accept` JSON)
- Respects `ignoreHTTPSErrors` when configured for that connection

```typescript
const api = SettingsHelper.getAPIConfiguration('CSRD');
// api.url, api.defaultHeaders, api.ignoreHTTPSErrors
```

Endpoints are usually passed separately to API helper methods; the configuration supplies **base URL and transport options**, not hardcoded routes in test code.

---

## Mandatory rules summary

| Rule | Detail |
|------|--------|
| **systemName** | **Required** on all high-level getters; identifies which `systems[]` entry to use |
| **No hardcoding** | Prohibit raw URLs and credentials in source — CI and local runs supply the generated `environment-configuration.json` |
| **Structure** | `systems[].{systemName}.connections[].{connectionType}.{param}` |
| **Optional params** | Use `getEnvParamOrNull` or dedicated helpers that return `null` when a connection is absent |

## Example: test scenario setup

```typescript
import { SettingsHelper } from '{config.importBasePath}/SettingsHelper';
import { TagHelper } from '{config.importBasePath}/TagHelper';

const SYSTEM = 'CSRD';
const TEST_ID = 'AUTH-001';

TagHelper.taggedTest(TEST_ID, async ({ page }) => {
  const baseUrl = SettingsHelper.getBaseUrl(SYSTEM);
  const { username, password } = SettingsHelper.getDefaultCredentials(SYSTEM);
  // Pass baseUrl, username, password into workflows — never embed literals
});
```

For database or SSH access, use the corresponding `SettingsHelper` methods (`getDatabaseSettings`, etc.) with the same **systemName** and appropriate **connectionType**.
