# Environment Configuration

This folder contains the templates and the script that produce **`environment-configuration.json`** — the config used by the test framework (SettingsHelper, DatabaseHelper, APIHelper).

---

## Overview

`environment-configuration.json` is a JSON document that defines systems and their connection settings. The framework reads it via `SettingsHelper` to resolve URLs, credentials, DB connections, SSH connections and OAuth/API settings by **system name**.

It is not only used at test runtime: the **AI generation agents read it too**, to resolve `{{SYSTEM.field}}` placeholders from a test descriptor and to reach the live application while researching locators. Generate it before starting a generation run.

`SettingsHelper` resolves the config in strict priority order, first hit wins:

| # | Source | Used when |
|---|--------|-----------|
| 1 | `/tmp/clone/environment-configuration.json` | pipeline run |
| 2 | `environment-configuration/local-environment-configuration/environment-configuration.json` | local run (generated by `setEnvironmentScript.ps1`) |
| 3 | `ATP_ENVGENE_CONFIGURATION` environment variable | **deprecated backward-compat fallback only** |

---

## Environment Configuration Template File

Use `environment-configuration/environment-configuration-template.json` as the contracted template for systems covered by ATs.

- Keep template values generic and reusable for all project environments.
- Project team owns this file and can update existing systems or add new ones.

Placeholders can be used to build connection properties for each system (for example `url`, `project`, `cluster`, `login`, `password`, `token`).
You can combine static text and multiple placeholders in one value.

Supported placeholders:

| Placeholder Name | Description | Example of value after replacement |
|------------------|-------------|------------------------------------|
| `${CLOUD_PROTOCOL}` | Protocol used to access ingress. | `https` |
| `${CLOUD_PUBLIC_HOST}` | Public DNS of the K8S cluster, used to construct publicly available ingress URLs. | `dev-1.k8s.sdntest.cloud.com` |
| `${CONSUL_PUBLIC_URL}` | Consul public URL (ingress). | `https://consul-dev-1.k8s.sdntest.cloud.com` |
| `${CONSUL_ADMIN_TOKEN}` | Consul admin token. | `s.XXXXXXXXXXXXXX` |
| `${DEFAULT_TENANT_ADMIN_LOGIN}` | Tenant Admin login. | `tenant-admin@example.com` |
| `${DEFAULT_TENANT_ADMIN_PASSWORD}` | Tenant Admin password. | `password!` |
| `${DEFAULT_TENANT_NAME}` | Tenant name. | `DefaultTenant` |
| `${ENVIRONMENT_NAME}` | Environment name. | `ci01` |
| `${ARGOCD_USER}` | ArgoCD user login. | `admin` |
| `${ARGOCD_PASSWORD}` | ArgoCD user password. | `password!` |
| `${K8S_TOKEN}` | Kubernetes API token. | `XXXXXXXXXXXXXX...` |

**Example:**

```json
      {
        "public-gateway": {
          "connections": [
            {
              "HTTP": {
                "url": "${CLOUD_PROTOCOL}://public-gateway-${ENVIRONMENT_NAME}-bss.${CLOUD_PUBLIC_HOST}",
                "login": "${DEFAULT_TENANT_ADMIN_LOGIN}",
                "password": "${DEFAULT_TENANT_ADMIN_PASSWORD}"
              }
            }
          ]
        }
      }
```

### Rendering in a pipeline run

In a pipeline the template is rendered automatically for the environment selected in the job:

- placeholders are replaced with real environment values;
- the result is written to `/tmp/clone/environment-configuration.json` — this file is what `SettingsHelper` reads (priority 1);
- the same JSON is also exposed in `ATP_ENVGENE_CONFIGURATION` for backward compatibility only.

The structure and the system/connection names are identical to a local run, so tests resolve the same systems either way.

## Top-Level Structure

```json
{
  "systems": [
    {
      "<systemName>": {
        "connections": [
          { "<connectionType>": { "<paramName>": "<value>", ... } }
        ]
      }
    }
  ]
}
```

| Level | Key | Description |
|-------|-----|-------------|
| Root | `systems` | Array of system objects. |
| System | `<systemName>` | Unique identifier of the system (e.g. `CSRD`, `public-gateway`). |
| System | `connections` | Array of connection objects. |
| Connection | `<connectionType>` | Identifier of the connection (e.g. `HTTP`, `DB`, `SSH`). |
| Parameters | `<paramName>` | Connection-specific keys (e.g. `url`, `username`, `password` for HTTP; `host`, `port`, `database` for DB). |

## Connection Types and Parameters

### HTTP

Used for: base URL, login credentials, API base URL, OAuth (token endpoint, client credentials, etc.).

#### System as application (UI or API)

| Parameter | Required | Description |
|-----------|----------|-------------|
| `url` | Yes | Base URL (e.g. `https://app.example.com`). |
| `username` / `login` | Yes* | Login username. *Required for UI login.* |
| `password` | Yes* | Login password. *Required for UI login / default credentials.* |
| `startPage` | No | Path appended to `url` for full app URL (e.g. `/app`, `/login`). Full URL = `url` + this path. |
| `ignoreHTTPSErrors` | No | `"true"` / `"false"` – to ignore HTTPS certificate errors for API. |

**Example:**

```json
"HTTP": {
  "url": "https://app.example.com",
  "startPage": "/app",
  "username": "login_user",
  "password": "login_password",
  "ignoreHTTPSErrors": "true"
}
```

#### System as authorization service (OAuth)

| Parameter | Required | Description |
|-----------|----------|-------------|
| `url` | Yes | Base URL of the auth server (e.g. `https://auth.example.com`). |
| `tokenEndpoint` | Yes | Path to OAuth token endpoint (e.g. `/oauth/token`). Full URL = `url` + this path. |
| `grantType` | No | OAuth grant type (e.g. `client_credentials`). |
| `clientId` | No | OAuth client ID. |
| `clientSecret` | No | OAuth client secret. |
| `scope` | No | OAuth scope (e.g. `openid profile api:read`). |
| `username` | No | OAuth username. |
| `password` | No | OAuth password. |

**Example:**

```json
"HTTP": {
  "url": "https://auth.example.com",
  "tokenEndpoint": "/oauth/token",
  "grantType": "client_credentials",
  "clientId": "client_id",
  "clientSecret": "client_secret",
  "scope": "openid profile api:read",
  "username": "username",
  "password": "password"
}
```

#### Combined (UI + API + OAuth)

One system used for UI steps, OAuth authentification and for API requests:

**Example:**

```json
"HTTP": {
  "url": "https://app.example.com",
  "startPage": "/app",
  "tokenEndpoint": "/oauth/token",
  "username": "user",
  "password": "password",
  "grantType": "client_credentials",
  "clientId": "client_id",
  "clientSecret": "client_secret",
  "scope": "openid profile api:read",
  "ignoreHTTPSErrors": "false"
}
```

### DB

Used for: database connection parameters.

| Parameter | Required | Description |
|-----------|----------|-------------|
| `type` / `db_type` | Yes | One of: `mysql`, `postgresql`, `mssql`, `mongodb`, `oracle`. |
| `host` / `db_host` | Yes | Database host. |
| `port` / `db_port` | Yes | Port. |
| `database` / `db_name` | Yes | Database name. |
| `username` / `db_login` | Yes | Database user. |
| `password` / `db_password` | Yes | Database password. |
| `connectionTimeout` | No | Connection timeout in ms (e.g. `10000`). |
| `queryTimeout` | No | Query timeout in ms (e.g. `30000`). |
| `ssl` | No | `"true"` / `"false"` – use SSL. |

**Example:**

```json
"DB": {
  "type": "postgresql",
  "host": "db.example.com",
  "port": 5432,
  "database": "app_db",
  "username": "db_user",
  "password": "db_password",
  "connectionTimeout": 10000,
  "queryTimeout": 30000,
  "ssl": false
}
```

**Example (using alternative parameter names):**

```json
"DB": {
  "db_type": "postgresql",
  "db_host": "db.example.com",
  "port": 5432,
  "db_name": "app_db",
  "db_login": "db_user",
  "db_password": "db_password"
}
```

### SSH

Used for: SSH connection parameters.

| Parameter | Required | Description |
|-----------|----------|-------------|
| `host` / `ssh_host` | Yes | SSH host address. |
| `username` / `ssh_login` | Yes | SSH username. |
| `password` / `ssh_password` | No | SSH password (for password-based auth). |
| `port` / `ssh_port` | No | SSH port (default: 22). |
| `workingDirectory` / `ssh_working_dir` | No | Working directory for remote commands. |
| `identityFilePath` / `ssh_key` | No | Path to SSH private key file (for key-based auth). |
| `passphrase` | No | Passphrase for encrypted SSH key. |
| `connectTimeoutSeconds` | No | Connection timeout in seconds. |
| `commandTimeoutMs` | No | Command execution timeout in milliseconds. |
| `strictHostKeyChecking` | No | Enable/disable strict host key checking (true/false). |
| `clientBinary` | No | Custom path to SSH client binary. |
| `passwordAuthBinary` | No | Custom path to sshpass binary (for password auth). |

**Example (password-based authentication):**

```json
"SSH": {
  "host": "host.example.com",
  "port": 22,
  "username": "ssh_user",
  "password": "ssh_password",
  "workingDirectory": "/home/ssh_user",
  "connectTimeoutSeconds": 30,
  "commandTimeoutMs": 60000,
  "strictHostKeyChecking": false
}
```

**Example (key-based authentication):**

```json
"SSH": {
  "host": "host.example.com",
  "username": "ssh_user",
  "identityFilePath": "/path/to/private_key",
  "passphrase": "key_passphrase",
  "workingDirectory": "/home/ssh_user"
}
```

**Example (using alternative parameter names):**

```json
"SSH": {
  "ssh_host": "host.example.com",
  "ssh_port": 22,
  "ssh_login": "ssh_user",
  "ssh_password": "ssh_password",
  "ssh_working_dir": "/home/ssh_user"
}
```

```json
        ]
      }
    }
  ]

```
